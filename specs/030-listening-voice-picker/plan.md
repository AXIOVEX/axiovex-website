# Plan — Spec 030 listening-edition voice picker

Implements the WF-04 amendment (docs/wireframes/wireframes.md,
2026-10-22) and spec.md in this folder. Decisions D1–D5 are from
the approved design package (2026-10-21), amended by the owner's
2026-10-22 decisions: **default = Brian; roster narrowed to
two voices — Brian and Sarah** (the package was sized for 4–6
voices with Wellington as default; the math is re-run below).

## Decisions

- **D1 — Rendering model: pre-render a fixed roster.** Every
  roster voice is rendered for the article catalog as static
  files by `scripts/build-listening.mjs` (the number-fidelity
  gate is on the script text, so it is voice-independent).
  Render-on-demand and browser text-to-speech were rejected in
  the package: first-listener latency and a paid-synthesis
  endpoint in the first case; an unpromisable roster in the
  second.
- **D2 — The Signals Briefing stays single-voice**, now Brian
  (the builder's pinned default voice, changed from Wellington
  2026-10-22). A briefing edition's data offers one voice, so
  the presence rule (FR-003) shows no picker there. Past
  editions stay as recorded.
- **D3 — Data model: extend, never break.** The default voice
  keeps the flat paths (`/assets/audio/<slug>/ch-NN.mp3`) and
  the flat `audio`/`durationSec` chapter fields; each other
  voice lives at `/assets/audio/<slug>/<voice-id>/` and in a
  per-chapter `voices` map in `chapters.json`, which also gains
  the `voices` roster list and `defaultVoice`. Single-voice
  data files (all briefings) remain valid unchanged. Sample
  clips: one shared sentence rendered per voice at
  `/assets/audio/voice-samples/<voice-id>.mp3`, played on a
  separate audio element that never touches edition state.
- **D4 — Switch + resume semantics.** Position is an anchor:
  chapter index + seconds into the chapter. A mid-edition
  switch reloads the same chapter at the same seconds-in,
  clamped to 2 s before that chapter's end in the new voice;
  play/pause state is preserved. Resume records gain a `voice`
  field; restoring in a different voice maps by chapter and
  fraction. Records with no `voice` field are read against
  the **default (Brian) track** — same chapter, same position
  (FR-006): the package's D4 text was written when Wellington
  was both the default and a roster voice; once the owner
  removed him from the roster, a legacy position can only be
  honored in the default voice's pacing.
- **D5 — Storage + disclosure.** The choice is localStorage
  `le-voice`, global across editions, sibling of `le-rate`,
  with the same try/catch degradation; nothing is sent to the
  site. The privacy policy §3 audio bullet gains "and narrator
  voice" in its own commit (FR-009).

## Build order

1. Builder roster support + default pin (Brian) + `--samples`.
2. Back-catalog render: Brian and Sarah synthesized per
   edition — 80 chapter files, 67,042 narration characters
   (2 × 33,521), plus 2 sample clips. Wellington's article
   audio leaves the deploy in the same commit (the flat paths
   become Brian's); the removal is named in that commit's
   message and his files stay recoverable in git history.
3. Player v4 (`blog/listening.v4.js` / `listening.v4.css`);
   `scripts/build-site.mjs` asset references bumped v3 → v4;
   affected pages regenerated by the deterministic site build.
4. Wireframe amendment + this spec committed; blog/README
   listening steps updated to the roster flow.
5. Privacy §3 edit as its own commit.
6. Staging verification as served (see tasks.md); production
   only on the owner's gate (FR-011).

## Cost (one-time, back catalog, as amended)

Per voice: 33,521 characters · 40 files · ~39 MB. Two-voice
roster: 67,042 characters · 80 files · ~78 MB added · ≈ $10–$20
at the package's $0.15–$0.30/1k-character planning range.
Largest single file stays ≈1.3 MB — far under the Pages 25 MB
per-file limit. Briefing recurring cost is unchanged (one
voice).
